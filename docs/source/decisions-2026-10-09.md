# Blueprint decisions, 9 October 2026 (gap review)

The owner asked Claude to "take the best decision" on the seven open items in the gap review (`reviews/blueprint-gaps.html`). These are the decisions applied to the blueprint. Every blueprint file must agree with this list. Decisions D1 to D3 (Razorpay first, fee payments never deleted, Transport not in the first sellable version) still stand. The new ones are D4 to D12.

## The seven decisions

| # | Question | Decided |
|---|---|---|
| D4 | Parent app or login? | **No parent app or password login in the blueprint yet. A Parent Link page is in the first sellable version.** Each guardian gets one personal, secure link by WhatsApp or SMS. It opens a phone-friendly page with no password; the first time it opens on a new phone, a one-time code goes to the guardian's registered mobile. It shows all their children in the school: fees due with a Pay button (Razorpay), receipts to download, attendance this month, notices, the datesheet, report cards once published, and consent forms. It is read-only apart from paying and giving consent. Parents still ask questions by WhatsApp or phone. The school can switch Parent Link off, choose what it shows, and revoke or reissue a link. Owned by 11 Communication (page "Parent Link"), built in Stage 2. A full parent app is planned as the first thing after Stage 4 and is not specified yet. |
| D5 | When do report cards arrive? | **Examination & Results moves into Stage 2, the first sellable version.** New build order: Stage 2 is 5 Communication, 6 Admission Management, 7 Fee Management, 8 Finance Management, 9 Attendance Management, **10 Examination & Results**, **11 Dashboard**. Stage 3 keeps 12 Homework & Learning, 13 Salary Management, 14 Front Office, 15 Events & Calendar, 16 Reports & Analytics. |
| D6 | Where do the safety basics live? | **In a new blueprint page, `08-platform-security.md`, built in Stage 1 with Settings.** It covers keeping each school's data apart, encryption, password hashing, backups and restore, rate limits, time-limited file links, the internal API with versioning and keys, webhooks from payment gateways, the attendance-device and GPS connections, background jobs, error monitoring, uptime and speed targets, offline sync rules and rules for the builder. These items leave the "Not included" list. Only DREAM TEAM SERVICES' own screens (school accounts, plans, billing, support tickets, system health views) stay with the Super Admin console (`07-super-admin.md`, owned by another thread). |
| D7 | Moving in from old software? | **New workflow 15, "Switching to School OS", plus imports for old fee dues, past receipts (kept read-only, marked "brought in"), cash and bank opening balances, enquiries, items and assets.** A school can start on any day of the year. |
| D8 | Indian rules | **(a) DPDP Act 2023:** a guardian gives consent for the child's data on the admission form or through Parent Link, confirmed by a one-time code to the guardian's mobile. Consent texts are versioned; each Consent Record keeps the version agreed to, and consent can be withdrawn. Existing students get a bulk consent request through Parent Link. Photo consent (for the gallery and social media) is one consent type. **(b) SMS DLT:** Settings stores the school's DLT entity ID and sender header; every SMS template stores its DLT template ID; an SMS can only be sent from a template with a DLT template ID. **(c) GST:** a fee head can be marked taxable with a GST rate; the school's GSTIN sits in School Profile; payments for taxable heads produce a tax invoice; a GST report exists. **(d) Financial year:** Finance Management has a financial year (default April to March) kept apart from the academic year; the Day Book, cash and bank books and finance reports work by financial year. |
| D9 | PF, ESI and TDS on salaries | **PF and ESI are calculated in the first version** (switch on in Salary Settings; default rates PF 12% employee and 12% employer on basic up to the wage ceiling, ESI 0.75% employee and 3.25% employer for wages up to the ESI limit; the school can change rates and ceilings). Professional Tax uses a state slab table, optional. **TDS is entered as a monthly amount per staff member, not calculated,** in the first version. Monthly PF and ESI statements are exported for the government portals. |
| D10 | School groups | **Add a Group record now.** A School may belong to one Group. One User Login can work in several schools through School Access entries (school or campus, roles, scope). Group screens still come later. |
| D11 | Phone apps | **The installable web app stays the app for staff.** Teachers on iPhones add it to the home screen for alerts (iOS 16.4 or later). **Transport (Stage 4) comes with a small native Android driver app** for reliable background location. A native parent app comes with the full parent app after Stage 4. |

## Clean-up decisions (no owner choice needed)

| # | Item | Decided |
|---|---|---|
| D12 | When salary and expenses reach the Day Book | **When marked paid**, because that is when money leaves. Expense statuses: Draft, Waiting for approval, Approved, Paid, Cancelled. Payroll Run statuses: Open, Calculated, Waiting for approval, Approved, Paid, Locked; one payroll run per month per campus. Salary advances also post to the Day Book when paid. |
| C1 | Starting roles | Ten ready roles, the same in every file: School Admin, Principal, Accountant, Teacher, Class Teacher, Receptionist / Front Office, Transport In-charge, Librarian, Hostel Warden, Store Keeper. Role templates the school can switch on: Vice Principal, Academic Head, HR, Office Staff, Exam In-charge, Admission Counsellor, Counsellor, Gate Security, Driver, Student. Office Staff does office work in workflows (student leave recording, substitutions, datesheet and admit cards, recording a student leaving). A User Login can belong to a Staff, Student or Driver record, so a hired driver can log in. |
| C2 | Status names | The module spec's names win; `04-data-model.md` uses the same names. |
| C3 | Message | A Message is one send to many people; each person is a Message Recipient with their own delivery status. |
| C4 | Gate Pass | Two kinds: Pickup (only guardians on the approved pickup list) and Hostel Outing (going with a named person, approved by the warden). |
| C5 | Leave Balance | Its own record (staff and, when switched on, students). |
| C6 | Calendar Entry types | Holiday, vacation, exam day, event, PTM, admission test. |
| C7 | System map | Every flow between modules described in a module spec has a numbered arrow. |
| C8 | Salary slip design | Listed in Settings, Document Designs. |
