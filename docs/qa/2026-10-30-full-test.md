## Decisions made (no questions asked)

1. PostgreSQL: extracted the official portable 16.10 zip already on disk (C:/Users/chala/tools/pg16.zip)
   into tools/pg16 instead of downloading it again; fresh data folder tools/pgdata, localhost only.
2. `.env` line 26 is a bare value that breaks shell sourcing; `.env` left untouched, db:setup run from
   tools/ with only the two DB passwords exported.
3. The build cannot finish on the D: hard disk: Turbopack's CSS (Tailwind) worker misses its deadline
   (Tailwind alone needs 94 s cold, 6 s warm; failed 3 times). Built and served from a copy on the SSD,
   C:\Users\chala\sos-build (robocopy without .git/node_modules/.next/tools/storage, `npm ci` 3 min,
   build 5 min), same local database and .env, STORAGE_DIR pointed at the D: storage folder. The repo on
   D: stays the source of truth; fixes are made and committed there, then mirrored and rebuilt.
4. Browser: the installed Chrome driven by Playwright, headless (no window on the screen, per the
   brain rule on probe windows), one fresh browser session per person (like separate profiles).
5. Lint: tools/ (portable PostgreSQL with pgAdmin JavaScript) and qa-output/ added to ESLint ignores.
6. Nothing outward: the log shows "No provider set up; development only" for WhatsApp/SMS/email, so no
   message leaves the PC; no Razorpay keys; never the live site.
7. E1: the Principal's decision step was run on the seeded Diya Patel (already sent to the Principal) instead of
   verifying Aarav's 6 papers first, to keep the run short; Aarav stays in Test & Interview.
8. E2: attendance locks at 11:00 and the test ran after 17:00, so attendance went through the correction path
   (teacher asks, Principal approves), which is what a school would do for a missed day.
9. One child (Kabir Sharma, Class 5 A) carries E2, E3, E6 and B6, so the parent's view checks them together.
10. Half Yearly results were not published (other subjects have no marks); report cards checked on Unit Test 2.
11. Parent Links for all of Class 5 were made (test mode, written to the log, nothing sent) to reach Kabir's father.
12. Typecheck: tsconfig now excludes tools/ and qa-output/ (313 errors, all from pgAdmin's TypeScript inside the
    portable PostgreSQL; 0 in School OS), the same as decision 5 for lint.
13. Crawls ran on the build that was already serving (before the fixes), to save a rebuild per role; fixes were
    re-checked after one rebuild at the end. Max pages per module: Principal 20, other roles 25, console 80.
14. "Controls without a name" from the crawl were checked by hand: export menus and forms inside a closed
    `<details>` (Chrome hides their text), and hidden file inputs driven by a visible button, are not problems.
    The checker (qa/lib.mjs) now skips them. One real one fixed: the Communication file input was in the tab order.
15. File downloads (exports, templates, bank files, invoices) open as downloads, as meant; the crawl lists them
    as "Download is starting" and they are not counted as failures.
16. Bug 5's second half (only the Principal may reject an admission, so an application the Principal sent cannot be
    rejected by the School Admin who approves it) is a blueprint rule, not changed; listed for the user.
17. Front Office, Visitors at 1440 px: the visitor table (860 px minimum) scrolls inside its card next to the side
    panel, so the row's "Check out" sits at the right edge. A layout choice of the shared Split/DataList, not a
    break; left as a UX note for the user rather than changing every page that uses Split.
18. Browser re-check after the rebuild: qa/full/recheck.mjs 13 of 13 PASS (bugs 2, 3, 4, 5, 7, 10, 11, 12, 13, 14),
    qa/full/co-now.mjs bug 9 PASS (checked out in the same minute). j9-visitor.mjs's own check-out step failed
    only because "Check out" is a link, not a button (script mistake, not the app).
19. "View only" on Homework, Front Office, Transport, Library, Inventory and Hostel for the Principal is the owner's
    duty rule (src/lib/duty.ts, prototype changes of 13-14 Oct 2026): oversight roles read desk pages and the
    server still allows Full. Not a bug.
20. Look and feel (G1) checked as the Principal on the main page of all 20 modules, light and dark, 390 and 1440 px
    (qa/full/looks.mjs, 80 screens, contact sheets in qa-output/full/looks/sheet-*.png, looked at by Claude).
    The first contrast run read Chrome's oklab() colours as RGB and reported false low-contrast text (phone bar,
    a hostel calendar day); the checker now converts every colour through a canvas and blends see-through text.
