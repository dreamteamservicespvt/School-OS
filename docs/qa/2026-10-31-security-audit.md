Written for: School OS owner and developers. Date: 2026-10-31.

## 1. Run facts

- Skill: Cloudflare security-audit-skill @ c1c8a8c1, full audit mode, **quick profile: a partial pass, not complete coverage.**
- Source ref: commit 0b67003b, branch claude/project-thread-cesreq, dirty worktree (owner's own edits, reviewed as present).

- Execution: sandboxed-source-and-local-only policy. ## 2. Posture

School-to-school isolation is strong: PostgreSQL row-level security under `withSchool()` and no DELETE right for the app role. None of the 13 reviewed units found a cross-school read or write. The weak spots are code-level rules inside one school, such as a role's reach and approval steps that each action must enforce on its own (the notice Undo skipped them), and fail-open fallbacks (two-step sign-in). Public token links, file links, the Razorpay webhook signature and the machine endpoints held up under source review.

## 4. Confirmed finding details

### Notice archive Undo lets any Communication Own-reach user republish an archived notice as PUBLISHED, skipping approval and author/campus checks

- Fingerprint: `school-os/undo/notice-archive-restore-without-reach-or-approval`
- Severity: likelihood medium, impact medium, overall **medium**. Confidence high.
- Source: src/app/(school)/undo-action.ts:9 -> src/lib/undo.ts:17 -> src/lib/communication/undo.ts:12 -> src/lib/communication/notices.ts:382 -> src/lib/communication/notices.ts:443
- Lower-trust principal: A Teacher with Communication Own reach in a school using the default notice approval rule ('parents').
- Reproduction (native interface, not executed): In a local dummy school, sign in as a Teacher and save a notice to their own section's parents as a draft.; Archive that draft with archiveNoticeAction.; Call the undoChange server action with kind 'notice-archive' and id '<noticeId>:PUBLISHED' (at any time, no window applies).; Read the notice row (status PUBLISHED, approvalId null), and open the Parent Link of a dummy guardian with a child in that section.
- Conditions: authentication_level A signed-in school staff session. A DREAM TEAM support browser is stopped earlier by the proxy, which refuses every non-GET request to school paths (src/lib/support-paths.ts line 53); note that SUPPORT_PERMISSIONS grant change 'all', so the handler's own permission check would not stop support. authorization_role Any role with Communication Own or wider, for example the ready Teacher, Class Teacher, Accountant, Receptionist and Transport In-charge roles. data_state For the approval bypass: the caller's own DRAFT notice, which they can always create for their own sections. For republishing another author's notice: the id of that archived notice, which the caller must already know (for example from an earlier board or notice link).
- Result: Not executed (no sandbox). Source trace establishes: the notice-archive handler accepts the call for Own reach; restoreNotice sets status PUBLISHED on the archived draft with no approval record and no author, campus or time check; noticesForGuardian returns PUBLISHED notices with the parent-link channel to matching guardians, so the notice appears on their Parent Link and on the staff board. No WhatsApp/SMS/app message is sent, because restoreNotice does not call publishNotice.
- Impact: Bypasses the school's notice approval for parent-facing notices (including notices the Principal sent back or rejected) and lets Own-reach staff republish withdrawn notices by other authors or on other campuses to parents and staff. Teacher-authored content cannot be CRITICAL and no messages are sent; no data is disclosed.
- Priority: Needs only a normal Own-reach staff login and one direct server-action call; the id format is visible in the archive toast's undo id. Republishing other authors' notices additionally needs a known notice id.
- Smallest fix: In the notice-archive undo handler, apply the same gate as archiveNoticeAction (commAction('archive'), which also refuses support, plus noticeOnCampus and the own-author check for non-full reach). Ignore the status in the client key and restore the status recorded server-side in the latest 'archived' audit entry. Require that the current user archived it and that it is within UNDO_WINDOW_MS. Add a regression test: a teacher calling undoChange('notice-archive', '<id>:PUBLISHED') on their own archived draft gets it back as DRAFT (or is refused after the window), and is refused for another teacher's archived notice.
- **Fixed on 2026-10-31:** src/lib/communication/undo.ts now uses commAction('archive') with the same campus and own-author checks as archiveNoticeAction, ignores the status in the client key, restores the status from the server's 'archived' Audit Log entry, and accepts Undo only from the person who archived it within UNDO_GRACE_MS (src/lib/undo.ts). Test: tests/communication/notice-approval.test.ts, "Undo of an archive brings back only the status...".

### Two-step login falls back to password-only sign-in when a school's SMS send fails (for example, no credits left)

- Fingerprint: `two-step/sms-send-failure-fails-open-to-password-only`
- Severity: likelihood low, impact medium, overall **low**. Confidence high.
- Source: src/app/sign-in/actions.ts:62 -> src/app/sign-in/actions.ts:65 -> src/lib/auth/two-step.ts:193 -> src/lib/auth/two-step.ts:110 -> src/lib/messaging/send.ts:691 -> src/lib/auth/two-step-sms.ts:63 -> src/lib/auth/two-step.ts:119 -> src/lib/auth/sign-in.ts:228 -> src/app/sign-in/actions.ts:69
- Lower-trust principal: An outsider who has obtained a School Admin, Principal or Accountant password (phishing, reuse) but not their phone, signing in through the public sign-in page while the school's SMS credits are exhausted (naturally, or after spending them through the public code sign-in form).
- Reproduction (native interface, not executed): Dummy setup only: a school with the two-step feature on, a role with requiresTwoStep, a login with a phone and no email, SMS channel on in live mode with DLT entity, sender header and a sign-in-code template DLT id, SMS credit balance 0, server mail not set up, NODE_ENV production and APP_URL not this computer.; Submit the sign-in form with the right username and password.; Observe whether the response sets sos_session and redirects to /profile?twoStep=add#password instead of /sign-in/code, and whether a signed-in-without-two-step Audit Log Entry is written.
- Conditions: authentication_level The attacker knows the correct password of a login whose role requires two-step login (School Admin, Principal or Accountant) and is not signing in from a remembered device. data_state The login has a mobile number and either no email address or server mail is not set up (mailIsSetUp false), so SMS is the only code channel. system_configuration The school's SMS channel is on and live (not test mode) with DLT entity, sender header and a sign-in-code template with a DLT template id, so signInSmsTemplate returns a template and sendMessage is actually tried. data_state The SMS send fails with a MessagingProblem at that moment, for example the school's SMS credit balance is below the code message's credit cost. system_configuration Running as a live server (not development and APP_URL not this computer), so mayLogCode('none') is false and the code is not written to the server log.
- Result: Not executed (no sandbox). Source trace establishes: signIn returns twoStep for the role; startChallenge calls deliverCodeTo; with no usable email it calls sendCodeBySms; signInSmsTemplate returns the template; sendMessage plans the SMS with a credit cost above a 0 balance, so recordSend throws MessagingProblem at send.ts line 691; sendCodeBySms returns { sent: false }; deliverCodeTo returns { unreachable: true }; startSecondStep calls completeSignIn with withoutTwoStep and returns kind 'signed-in'; signInAction calls finish(), which sets the session cookie, and redirects to /profile. The person is signed in with the password only.
- Impact: The second factor for the most privileged school roles (School Admin, Principal, Accountant) is skipped, giving a full session over the school's records and money screens to a password-only attacker; the event is audited as signed-in-without-two-step but not prevented.
- Priority: Requires a known password for a two-step-role login, that login having no usable email channel, SMS set up for the school, and a failing SMS send (credits exhausted) at sign-in time; credit exhaustion can occur naturally or be driven by outsiders through the rate-limited public code sign-in form.
- Smallest fix: Make sendCodeBySms report 'not set up' separately from 'tried and failed', and have deliverCodeTo return a blocking problem (no unreachable flag) when an SMS send was tried for a configured channel and failed. Keep the password-only fallback only for the not-set-up cases. Optionally exempt one-time sign-in codes from the credit block (or give them a reserved allowance) so admins are not locked out when credits run out, and add a test: SMS set up, credits 0, phone-only two-step login gives kind 'problem'.
- **Fixed on 2026-10-31:** src/lib/auth/two-step-sms.ts returns a problem when SMS is set up but the send fails; src/lib/auth/two-step.ts deliverCodeTo returns that problem (no unreachable flag), so startSecondStep refuses instead of signing in with the password alone. Test: tests/communication/two-step-sms-fails.test.ts.

## 6. Hardening notes (not findings) and positive patterns

- src/app/(school)/student-management/import/[batchId]/errors/route.ts requires only student-management 'create' (Own reach passes), while the import pages require can.manage, and it does not filter by campus. Require manage (and campus) so a teacher who learns a batch id cannot read an import's raw skipped rows.
- archiveNoteAction in src/app/(school)/student-management/_actions/students.ts checks the posted studentId, but archiveNote in src/lib/students/records.ts does not bind noteId to that student. A campus-limited manager could archive a note on another campus's student if they knew its id. Add studentId to the note lookup.
- src/lib/undo.ts defines UNDO_WINDOW_MS but leaves time and actor binding to each handler, and several handlers (front-office notes and appointments, events, academic) rely only on role capability. Consider binding the actor and window centrally with a server-side undo token instead of client-held keys.
- CSV formula guard missing in three writers: errorCsv in src/lib/importer.ts (rows-with-problems download), the client-side marks import template in src/app/(school)/examination-results/marks/marks-grid.tsx (student names, which can start as public applicant names), and csvCell in src/lib/move-in/prepare.ts. Reuse the =+-@TAB/CR prefix guard from src/lib/exports.ts for consistency.
- public/push-sw.js accepts a link that starts with a slash followed by a backslash (browsers read it as a protocol-relative URL). The server's safeLink already refuses backslashes, so it is unreachable today. Add the same backslash check to the worker for defence in depth.
- The ICS esc() in src/app/api/v1/calendar/[schoolId]/[file]/route.ts escapes CRLF and LF but leaves a lone CR. Staff-entered titles or venues with a bare CR could split ICS lines in lenient parsers. Strip CR first.
- next.config.ts CSP sets no script-src, so stored-XSS defence rests entirely on React escaping and the absence of HTML sinks for user text (verified for this unit). A nonce-based script-src would add a second layer.
- The Parent Link, survey, receipt, calendar and album HMACs and the file-link HMAC fall back to FIELD_ENCRYPTION_KEY when PARENT_LINK_SECRET or FILE_LINK_SECRET is unset. The prefixes keep them domain-separated, but separate secrets would limit how far one leaked key reaches.
- tryOtp in src/lib/admission/consent.ts compares code hashes with !== rather than timingSafeEqual. The 5-try cap makes this immaterial; noted for consistency with the Parent Link code check.
- POST/GET /api/v1/jobs/tick has no shared secret (.github/workflows/job-tick.yml calls it bare). Add an optional JOB_TICK_SECRET bearer check so anyone on the internet cannot trigger bursts; today the rate limits and due-only job claiming keep the impact to load.
- Attendance punches have no lower bound on punch time (only >5 min in the future is refused), so a leaked device key can add new present/late marks on any past school day where no mark exists, including locked days (src/lib/attendance/devices.ts checkPunch/markFromPunch). Consider refusing punches older than the device's offline window, or past the lock date, unless a staff member reprocesses them.
- MSG91 delivery-report key travels in the URL query (?key=) and has no minimum length or generated value (src/lib/messaging/channels.ts webhookKey 'any long random word'). Generate it server-side (32+ random bytes) and keep URLs out of access logs.
- Console WhatsApp passOn (src/lib/console/whatsapp-webhook.ts) forwards every unauthenticated POST to CONSOLE_WHATSAPP_FORWARD_URL and echoes up to 1000 bytes of that site's answer before School OS checks the signature. Forwarding only signed bodies when CONSOLE_WHATSAPP_APP_SECRET is set would stop School OS acting as an open relay to the gym's site.
- School and messaging webhooks accept a validly signed body with no freshness check (no timestamp window, no event-id dedupe for incoming STOP/START). Effects are idempotent or forward-only, but a recorded signed START could undo a later STOP if it were ever replayed.
- SMTP provider (src/lib/messaging/providers/smtp.ts) on ports 25/587/2525 uses opportunistic STARTTLS (no requireTLS), so a STARTTLS-stripping on-path attacker could see the school's SMTP password. Set requireTLS: true for every port except 465.
- saveChannel keeps stored secrets when the provider is unchanged and the secret box is left blank, even if the SMTP host changes, so a console 'connect' user can re-point the host and receive the existing password they cannot view. Require the secrets again when host/user/fromAddress change.
- encryptField/decryptField (src/lib/crypto.ts) use AES-256-GCM without AAD and without authTagLength, so a ciphertext is not bound to its school/row/field, and Node accepts truncated tags. Pass authTagLength: 16 and bind schoolId+field as AAD in a v2 format (only matters to someone with DB write access).
- Payment confirmation on the school Razorpay webhook records gatewayAccountId from the URL rather than checking link.gatewayAccountId; in a school with two Razorpay gateways a mismatch is only mislabelled reconciliation, but comparing them would catch configuration mistakes.
- Console code check (src/lib/console/auth.ts checkConsoleCode) has no per-user check limit like the school's two-step:check (20 per 15 min), and consoleCodeAction has no IP limit. attempts is read, then incremented, so concurrent wrong guesses on one challenge can exceed MAX_CODE_TRIES. Add hitLimit('console-code-check:<userId>') and make the increment conditional (attempts < 5) in one statement.
- Vercel test copy (src/lib/test-copy-env.ts, testCopyCode in src/lib/console/auth.ts): the console sign-in page shows the second-step code, and seeds use DEMO_PASSWORD (default SchoolOS@2026). Anyone who knows the demo console password signs in to that copy. Keep test copies free of real school data and off public links.
- Changing the email and phone in My profile (src/lib/auth/two-step.ts startContactChange/confirmContactChange) needs only a session and a code to the NEW contact, as the blueprint says. A stolen session can therefore replace both second-factor contacts, then use code sign-in for lasting access. Consider asking for the current password, or a code to the old contact, before changing them.
- setTwoStep(false) in src/app/(school)/profile/actions.ts turns off self-chosen two-step with only a session; consider asking for the password.
- Two-step is decided at sign-in (needsTwoStepInAny). A role that needs two-step, or a new school access given while a session is open, is used without a code until the next sign-in, and switchSchool does not re-check. Consider re-checking on a role or access change.
- findLogin (src/lib/auth/sign-in.ts) matches the username before the mobile number. A school admin who creates a username equal to another person's mobile number makes that person's mobile-number sign-in fail, and their failed attempts are logged in the creator's school. Refuse usernames that look like phone numbers belonging to another login.
- acceptInvite (src/lib/auth/invites.ts), used after an expired-password sign-in, sets a new password without revoking the login's other sessions or remembered devices, unlike changePassword.
- changeOwnPassword in src/lib/console/team.ts revokes other console sessions but not trusted console devices (sos_console_device). The password is still needed, so this only lets a 30-day trusted device skip the code after a password change.
- Per-user lockouts (5 wrong passwords lock for 15 minutes) for console and school logins can be triggered by anyone who knows the login identifier (a mobile number), so the Owner's console login can be kept locked. This is availability only.

Positive patterns seen in source: row-level security on every school table, with `school_os_app` lacking BYPASSRLS and DELETE; HMAC-signed public links with timing-safe compares; the Razorpay webhook signature checked before parsing; money as BigInt paise with row locks on the six race-prone money paths; support access refused for changes in both the proxy and `requireAction`; a CSP header.
