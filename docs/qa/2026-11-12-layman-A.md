## Problems

### LA1 (Medium) Date boxes are emptied when the server refuses a form
- Steps A (Add student): Student Management > Add student. Fill everything, Date of birth 10-06-2019, but a full name longer than 120 letters. Press Add student.
- Steps B (New application): Admissions > enquiry > Convert to application. Date of birth 15-08-2030, fill the rest, confirm the consent code, Save application.
- What happened: the red message comes back ("Full name can be at most 120 characters." / "Date of birth cannot be in the future."), the other boxes keep what was typed, but **Date of birth is now empty** ("Date of birth is needed." on the next press). A clerk who only fixes the named mistake gets a second refusal.
- Should: every box keeps what was typed after a refusal; only the wrong box is marked.
- Note: once (script clearing the box with fill("")), the box showed 05-05-2022 while the save still said "cannot be in the future"; typing like a person (select all, Backspace, type) saved correctly, so that part is not confirmed.
- Screenshots: `qa-output/layman-a/sn-saved.png`, `qa-output/layman-a/sn2-after-refuse.png`, `qa-output/layman-a/app-saved.png`.
- Likely source: `src/components/ui/date-input.tsx` (`useHeld`, the form `reset` listener sets the held value back to `defaultValue` when React resets the form after the server action).

### LA2 (Medium) Add class: after a double click the box stays open with an old error, although the class was saved
- Steps: Academic Management > Classes & Sections > Add class. Type "Class 2" > Add class (message "Class 2 already exists in this year"). Change the name to a new one and double-click Add class.
- What happened: the class is created once, but the box stays open still showing "Class 2 already exists in this year. Add a section to it instead." The clerk thinks it failed and tries again. (With a single click the box closes correctly.)
- Should: after a good save the box closes (or shows "Added"), and the old message is cleared.
- Screenshot: `qa-output/layman-a/class3-dbl.png`. Likely source: the Add class dialog under `src/app/(school)/academic-management/` (class form action / dialog close on success).

### LA3 (Medium) Class 5 A attendance numbers disagree between screens; a moved student shows as "(left)"
- Steps: as the class teacher of 5 A, open Take Attendance for today, then Attendance Register, then (as admin) Dashboard.
- What happened: Take Attendance lists 15 students (13 present, 1 absent, 1 late). Register header says "Class 5 A · 16 students · 87.5% present" and Dashboard "Students present 14 / 16 · 2 absent". The 16th is Ananya Verma, moved to 5 B today (Roll 17), shown in the 5 A register as "Ananya Verma (left)" with an A for today. "(left)" reads as if she left the school; she is studying in 5 B.
- Should: one count everywhere for the day, and the label "moved to 5 B on 12-11-2026" (or similar), not "(left)".
- Screenshot: `qa-output/layman-a/att-reg-teacher.png`, `qa-output/layman-a/att-t-today.png`. Likely source: register and dashboard counts (`src/lib/attendance/*`, `src/lib/dashboard/widgets/attendance.ts`).

### LA4 (Low) Take Attendance for a date in a past year shows the class anyway
- Steps: Take Attendance > Date box > type 01-04-2025 > Enter.
- What happened: the message "Pick a date on or after 01-04-2026." appears, but under it the page still shows Class 5 A for "Tuesday 1 April", "Attendance for 01-04-2025 locked ... Request a correction" and all 15 students as Not marked.
- Should: show only the message (or the closed year's read-only register), not offer a correction for a day outside the year.
- Screenshot: `qa-output/layman-a/att-t-01-04-2025.png`. Source: `src/app/(school)/attendance-management/page.tsx`.

### LA5 (Medium) Under load the server runs out of database connections and shows the crash page
- Steps: 5 testers on the same server; as Receptionist type `/attendance-management/settings`.
- What happened: "School OS could not open. Something went wrong on our side." The server log says `PrismaClientKnownRequestError: Timed out fetching a new connection from the connection pool (connection pool timeout: 10, connection limit: 9)`. `tools/app.log` has 27 such lines today (dashboard, student list, admissions, attendance settings, reports).
- Re-check: the same address a few minutes later gave the correct "Attendance Management is not in your menu" page for Receptionist and Accountant, so the access rule is right; the crash came from the database pool.
- Should: a busy moment must not show the crash page. At 9 AM every class teacher marks attendance at once, so a pool of 9 may be too small for one school, let alone many. Check the pool size and connection reuse for production (`DATABASE_URL` `connection_limit`, Prisma client per request) and show "Busy, try again" instead of the error page. Goes with LA10.
- Screenshot of the refusal on re-check: none needed; log lines in `tools/app.log` (search "Timed out fetching a new connection").

### LA6 (Low) Name boxes accept any length until Save
- Steps: Add student > paste a 250-letter name.
- What happened: the box takes it all; only after pressing Add student does "Full name can be at most 120 characters." appear (and LA1 then empties the date). The enquiry and email boxes do have a limit.
- Should: the box stops at 120 letters (maxlength) or warns while typing.
- Screenshot: `qa-output/layman-a/sn-saved.png`.

### LA7 (Low) Enquiry child name made only of emoji, or parent name "1", is not questioned
- Steps: Add enquiry > Child's name "😀😀", Parent's name "1", bad phone. Press Add enquiry.
- What happened: messages for phone, email and follow-up date, none for the names.
- Should: "Type the child's name in letters" (same check as other name boxes).
- Screenshot: `qa-output/layman-a/enq3-after.png`, `qa-output/layman-a/enq-bad.png`.

### LA8 (Low) Some refused pages silently jump to the Student List
- Steps: as Teacher type `/student-management/promotion`, `/leaving/new`, `/certificates/new`, `/settings`, `/logins`; as Accountant or Receptionist type `/student-management/behaviour`, `/behaviour/counselling`, `/import`, `/certificates/new`, `/settings`.
- What happened: the Student List opens with no word about why. Admission, Academic and Attendance addresses show the "no access" page instead.
- Should: the same "This page is not for your role" message everywhere, so people know the link was refused, not broken.
- Log: `qa-output/layman-a/roles.log`.

### LA9 (Low) Two staff with the same name cannot be told apart in the enquiry Owner filter
- Steps: Admissions > Enquiries > Owner filter.
- What happened: "Naresh Kumar" appears twice. The Add enquiry box shows the job ("Receptionist" / "Teacher"), the filter does not.
- Should: add the job title in the filter too.

### LA10 (Low, needs re-measure) Many screens take 5 to 18 seconds to open
- Measured while 5 testers used the same dev server: Teacher Allocation (teachers view) 18.6 s, Subjects 15.2 s, Enrolment edit 15.2 s, Guardians 14.5 s, Academic Settings 14.5 s, Syllabus 14.5 s, Academic import 13.3 s, Alumni jobs 12.7 s, Student list 11.0 s.
- Should: under 3 seconds (test plan question 6). Re-measure on the production build before treating as a defect. Data: `qa-output/layman-a/crawl-admin.json`.

### LA11 (Low) School Admin is told "Full" for Attendance but the screens say "View only"
- What happened: Settings > Users > Suresh Kumar shows Attendance Management "Full" and the School Admin role says "Everything, in every module", but Attendance shows a "View only" badge and hides Take Attendance and Student Leave (typed address `/attendance-management/student-leave` jumps to the register). This is on purpose in `src/lib/duty.ts` (owner prototype 13-14 Oct), but the words disagree, and in this demo school nobody in the office can record a student's leave (Receptionist is refused; the Office Staff template is off).
- Should (owner decision): either say in Settings "Takes no class register" for oversight roles, or let the School Admin record student leave.

### LA12 (Low) New application does not flag a future date of birth on screen
- Steps: New application > Date of birth 15-08-2030 > Save.
- What happened: no on-screen message until the consent code is done and the server answers. Add student flags the same date at once ("Pick a date on or before 12-11-2026").
- Should: same on-screen check as Add student (max = today).
